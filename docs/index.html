Features

Connecting is the easy part.

The hard part is what happens around the tunnel: a resolver that silently died, a route out of the wrong interface, an Ethernet port without internet stealing Wi-Fi. StoneVPN watches all of it.

Four VPNs, one switchboard

WireGuard via wg-quick, OpenVPN via the Homebrew binary (it writes routes correctly, unlike the GUI), Defguard with MFA, and Cisco Secure Client with in-app login and Duo push. Favourites, aliases, last used.

DNS doctor

Notices a dead resolver within seconds, purges entries left by dead tunnels and bounces the service so macOS really recomputes DNS. If a live-but-broken VPN is the culprit, it says so instead of pretending.

Primary DNS & split DNS

Pick whose resolver answers first — WireGuard, Cisco, Defguard or the system — and route internal domains with /etc/resolver rules. Common mistakes (an interface IP instead of a DNS server) get flagged.

DNS guard after WireGuard

wg-quick writes its DNS on every service and doesn't always put it back. The app remembers each service's baseline and restores it after disconnect, so the next VPN's hostname still resolves.

Route-fix & VPN-in-VPN

When macOS sends the handshake out the wrong interface, host routes to the VPN server go via your LAN gateway — per profile, remembered. Stale routes from yesterday's Wi-Fi are purged before every connect.

Network priority that makes sense

macOS picks the primary interface by service order, not by internet. An Ethernet port into a dead router wins over working Wi-Fi. See real per-interface reachability and fix it with one click.

Stale Defguard sessions

After a long sleep the gateway drops your MFA session while macOS still says “Connected” — and every DNS query black-holes. StoneVPN detects it, turns red and renews the session with just a new code.

A helper that can't be talked into things

Root work runs in a small daemon that accepts only the app's own signature and a fixed set of checked operations — paths, IPs, service names, PIDs. No shell strings, no passwords in arguments.

A real CLI behind it

Prefer the terminal? main-vpn-manager.sh does the same: status, up, down, dns fix, route, net auto. App and CLI share config.env — or the app runs on its own.

How it works

Root only where it has to be.

The app runs as you. Anything that needs root goes to a launchd daemon as a typed request, gets validated, and runs — or doesn't.

  • Signature-pinned XPC. The helper accepts connections only from the app bundle it ships in.
  • Every argument checked. WireGuard configs only from WireGuard dirs, IPs parsed, service names matched, only tunnel PIDs killed.
  • No helper? Still works. Each root action then asks for your password once, via the standard macOS prompt.
  • Status never prompts. Reading state is sudo-free; root-only reads are skipped without the helper.

Install

FAQ

Good questions.

Why does macOS warn about the app on first launch?

It is free and signed ad-hoc, without a paid Apple Developer ID. The Homebrew cask removes the quarantine flag for you. With the manual .zip, run xattr -cr /Applications/StoneVPNManager.app once, or right-click → Open. Updates are verified with an EdDSA signature.

What exactly runs as root?

wg-quick, openvpn, DNS and route changes, network service order and stopping tunnel processes — through the helper, and only as typed, validated operations. Defguard and Cisco go through their own CLIs and need no root at all.

Does it send anything anywhere?

No telemetry, no accounts. Network traffic is limited to the update check (an appcast on GitHub Pages), DNS probes (dig apple.com) and reachability probes per interface. That is also why macOS asks for Local Network access — your resolver usually lives in the LAN.

Do I need the Bash scripts or the git repo?

No. Without the repo the app keeps its settings in ~/Library/Application Support/StoneVPNManager/. If you clone the repo, app and CLI can share config.env and state.env.

Which languages does the app speak?

English and Ukrainian. It follows the system language (or the per-app language in System Settings); Settings → General → Interface Language overrides it. Even messages from the root helper come back in the app’s language.

How do I update or uninstall?

The app checks for updates itself (Settings → General). With Homebrew: brew upgrade --cask --greedy stone-vpn-manager. To remove: Settings → Helper → Remove, then brew uninstall --cask --zap stone-vpn-manager.
