Можливості

Підключитись — найпростіше.

Складне — все навколо тунелю: резолвер, що тихо помер, маршрут не через той інтерфейс, Ethernet без інтернету, який забирає трафік у Wi-Fi. StoneVPN стежить за всім цим.

Чотири VPN — один пульт

WireGuard через wg-quick, OpenVPN через Homebrew-бінарник (він, на відміну від GUI, правильно прописує маршрути), Defguard з MFA і Cisco Secure Client з логіном і Duo push прямо в застосунку. Обрані, псевдоніми, останній профіль.

DNS-доктор

За секунди помічає мертвий резолвер, прибирає записи мертвих тунелів і «перебиває» сервіс, щоб macOS справді перерахувала DNS. Якщо винен живий, але зламаний VPN — чесно про це скаже.

Основний DNS і split DNS

Обери, чий резолвер питати першим — WireGuard, Cisco, Defguard чи системи — і направ внутрішні домени правилами /etc/resolver. Типові помилки (IP інтерфейсу замість DNS-сервера) підсвічуються.

Повернення DNS після WireGuard

wg-quick ставить свій DNS на всі сервіси і не завжди повертає старий. Застосунок пам'ятає еталон кожного сервісу і повертає його після відключення — адреса наступного VPN резолвиться.

Route-fix і VPN у VPN

Коли macOS шле хендшейк не через той інтерфейс, host-маршрути до VPN-сервера йдуть через твій LAN-шлюз — окремо для кожного профілю, з пам'яттю. Мертві маршрути від учорашнього Wi-Fi прибираються перед кожним підключенням.

Пріоритет мережі з глуздом

macOS обирає первинний інтерфейс за порядком сервісів, а не за наявністю інтернету: Ethernet у мертвий роутер перемагає робочий Wi-Fi. Бач реальну доступність кожного інтерфейсу і виправ одним кліком.

Протухлі сесії Defguard

Після довгого сну gateway скидає MFA-сесію, а macOS і далі пише «Підключено» — і всі DNS-запити зникають. StoneVPN це бачить, червоніє і оновлює сесію лише з новим кодом.

Helper, якого не вмовиш

Root-дії виконує маленький демон, що приймає лише підпис самого застосунку і фіксований набір перевірених операцій — шляхи, IP, назви сервісів, PID. Жодних shell-рядків, жодних паролів в аргументах.

Справжній CLI під капотом

Любиш термінал? main-vpn-manager.sh робить те саме: status, up, down, dns fix, route, net auto. Застосунок і CLI ділять config.env — або застосунок працює сам.

Екрани

Нативно, тихо, чесно.

SwiftUI-поповер у menubar для щоденних кліків, вікна — для решти. Колір = стан: зелений — працює, помаранчевий — підключається, червоний — зламано, фіолетовий — «мережу тримає хтось інший».

Резолвери з живою перевіркою, хто власник DNS, перемикач основного DNS і твої split-правила — Fix і Flush на відстані кліку.

Усі профілі всіх бекендів: псевдоніми для незрозумілих назв .ovpn, обрані й політика route-fix для кожного профілю.

Логін OpenVPN з OTP і вибором route-fix шлюзу. Паролі й коди ніде не зберігаються.

Який тунель що везе: маршрути кожного utun з підписом власника, плюс host-маршрути до VPN-серверів.

Ті самі ключі, що в config.env, плюс повернення DNS, doctor і автоматика.

Макети з вигаданими даними (документаційні діапазони IP, хости example.com) — не знімки чиїхось реальних мереж.

Як це працює

Root — лише там, де без нього ніяк.

Застосунок працює від твого імені. Усе, що потребує root, іде до launchd-демона типізованим запитом, перевіряється — і виконується або ні.

  • XPC з прив'язкою до підпису. Helper приймає з'єднання лише від того бандла застосунку, в якому лежить.
  • Кожен аргумент перевірено. Конфіги WireGuard — лише з тек WireGuard, IP розбираються, назви сервісів звіряються, зупиняються тільки процеси тунелів.
  • Без helper теж працює. Тоді кожна root-дія разово питає пароль через стандартне вікно macOS.
  • Статус ніколи не питає пароль. Читання стану — без sudo; root-only читання без helper просто пропускаються.
CLI

Той самий мозок — у терміналі.

Застосунок виріс із набору Bash-скриптів, і вони нікуди не ділись. Клонуй репозиторій — і обидва ділитимуть один конфіг.

FAQ

Слушні питання.

Чому macOS попереджає про застосунок при першому запуску?

Він безкоштовний і підписаний ad-hoc, без платного Apple Developer ID. Homebrew-cask сам знімає прапорець карантину. Для ручного .zip один раз виконай xattr -cr /Applications/StoneVPNManager.app або правий клік → Open. Оновлення перевіряються підписом EdDSA.

Що саме працює від root?

wg-quick, openvpn, зміни DNS і маршрутів, порядок мережевих сервісів і зупинка процесів тунелів — через helper і лише як типізовані перевірені операції. Defguard і Cisco йдуть через власні CLI і root не потребують.

Чи надсилає він кудись дані?

Ні телеметрії, ні акаунтів. Мережа — лише перевірка оновлень (appcast на GitHub Pages), перевірка DNS (dig apple.com) і доступності кожного інтерфейсу. Тому macOS і питає дозвіл Local Network — резолвер зазвичай живе в LAN.

Чи потрібні Bash-скрипти або git-репозиторій?

Ні. Без репозиторію застосунок тримає налаштування в ~/Library/Application Support/StoneVPNManager/. Якщо склонуєш репо — застосунок і CLI ділитимуть config.env і state.env.

Якою мовою інтерфейс?

Українською та англійською. Застосунок бере мову системи (або мову застосунку в System Settings); перевизначити — Налаштування → Загальні → Мова інтерфейсу. Навіть повідомлення root-helper приходять мовою застосунку.

Як оновити або видалити?

Застосунок сам перевіряє оновлення (Налаштування → Загальні). Через Homebrew: brew upgrade --cask --greedy stone-vpn-manager. Видалити: Settings → Helper → Видалити, потім brew uninstall --cask --zap stone-vpn-manager.
